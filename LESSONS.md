# Lessons

- **A request is not an outcome.** `NSRunningApplication.activate` returns before the app is in front, and the call that depended on it went out at once and logged "focus handed back". Wait for the evidence, bounded (an activation note for that pid or a short poll, at most 1 s: `FocusHandoff`), act after it, and log "requested", "confirmed" and "failed (timeout)" as three different lines.
- **`a ?? b` is not a fallback chain when `a` can be present and wrong.** `system ?? app` tried the app's focused element only when the system query returned nothing; a foreign or window-less system element ended the search. Validate each candidate fully (owner, window, the window's owner) and move on at the first failure (`FocusedWindowResolver`).
- **Every exit of a state machine owns the cleanup of what was opened on the way in.** The no-target path sent Shep home but left the voice session it had opened, and a late transcript could still submit. Make the cleanup an effect of that transition (`.cancelVoice`), so no caller can forget it.
- **A log line deduplicated on its output hides its inputs.** The target line printed only when the source changed, so a VoiceOver toggle that left the source alone was invisible, and the flag the choice used was never written. Print what was sampled (the flag, the fixed reason per candidate) and dedupe on the whole line.
- **A model's pick is evidence, not a decision.** The namer pointed at a whole pane (45 % of the window) and the pipeline skipped its own ranking because the model had "decided"; in another run it pointed at a button that shares no word with the request while one listed control matched it uniquely. A pick is checked against what the code can see for itself: not pane-sized (`ProposalRanker.isPaneSized`), and not outranked by a unique strong match on the request words.
- **Do not blame the coordinates before testing them.** Three displays with negative origins looked like the cause of four failures. A pure test on the exact layout (`ThreeDisplayGeometryTests`) showed the conversions are right, and the causes found were a pane-sized pick and a one-sample process lookup. Pin the geometry first, then look elsewhere.
- **One failed sample is not an absence.** The recording watch deleted the clip and said "the target app is gone" because one `NSRunningApplication` lookup came back empty while the window server still listed the window. Let the stronger source decide alone, tolerate the weaker one for a few ticks, ask it a second way, and when it still fails say what failed ("could not confirm"), not what you guess happened.
- **A log that says "nothing" must say why.** `tint: skipped (not-docked)` and `Shep did not arrive` do not carry the dock plan's own note, and the detector's boxes are not in the debug dump, so two causes here are inferred instead of read. Put the reason next to the verdict.
- **A wake word needs an end, not just a start.** Push-to-talk ends on key-up; "Hey Shep" has no key, so the call needs its own end-of-speech rule (1.5 s of silence, 6 s if nothing was heard) or it would hold the microphone for the full 30 s. It lives in `WakeWordPolicy`, where it is tested.
- **Never log what a listener hears.** The wake-word log formatter takes no String at all (constants and a closed error enum), so a transcript cannot reach a log line by accident; a test pins the whole set.
- **A growing partial transcript repeats its match.** The recogniser re-sends "hey shep ..." with every new word, so the detector counts occurrences per recognition task and reports only a new one.
- **Swap the request, not the engine.** The recogniser stops a task at about a minute; replacing the request under a running tap restarts recognition without closing and reopening the microphone (and without flickering the indicator).
- **A check that cannot fail is not a check.** The dock-time verify compared only the dog's size, and the hidden dog still had its default 40x28, so an unplaced dog (`placed:false`, at 0,0) passed as "ok". It now needs `placed`, the right position and a dog-inside-tab test. Commands to the page also wait for a `{ready:true}` handshake instead of being dropped when `window.shep` does not exist yet, and the layout is re-sent up to 3 times.
- **Never let the page size the dog from "100%".** The first real docked screenshot showed a ~200 pt head: when the layout did not reach the page, `#dog` fell back to the whole 320 x 212 panel. The dog is now tab-sized and hidden until `setLayout` places it, `shep.metrics()` reports what the page did, and the dock-time log compares it with the computed rectangles (and re-sends the layout on a mismatch).
- **A tab in the title-bar colour on a dark background needs a visible hairline.** Dark outline is now 22 % white; the fill runs 1 pt past the base so the window's own border does not show along it.
- **The test window must have room above it.** A window 22 pt under the menu bar cannot hold a 30 pt tab, so it gets the inside tab. `scripts/shep-test-window.sh` moves the window to (200, 200) through the Accessibility API so the normal case is what gets captured.
- **Capture only what you need.** `docked-shot.sh` pads above the tab only; left, right and below are the window's own bounds, so neighbours are not recorded.
Newest first. Add an entry whenever the Mac build or a run teaches us something.

- **A model's name for its own box is not a match.** Run 1 (display above) clicked empty toolbar space: the namer drew a box no detector found, named it with the request's words, and that name made it a "strong match" that tied the real checkbox, so the one-strong-match rule went silent and the ranking never ran. Evidence that only the model can see (a screenshot-only control and the label it gave it) does not outvote what the app lists; and a click with nothing nameable under it falls back to the listed controls instead of refusing. The counts proved it (`found=4` from 3 offered candidates); read the counts before blaming coordinates.
- **Name the test class, not the file.** `-only-testing:ShepCoreTests/LiveDebugTests` ran nothing (the class is `LiveDebugFilesTests`), and a dropped space shipped in one commit. A targeted run that reports fewer tests than expected is a wrong filter; the full `scripts/test.sh` is the check.

- **Do not say "done" or "never started" while the work is still in flight.** After the target left, the recorder waited 30 s for a start, then reported `recording-discarded refused` and `neverStarted` although `startCapture` had not returned; the script then stopped Shep and a clip could remain. Await the real task (a task you launched and kept, with a flag set synchronously at the launch), bound every wait, and when a bound runs out say `unknown` in its own status event (`discard-unknown`). `never-started` is only true when no task was ever launched. A stop that can hang gets a timeout that does not wait for the hung call (`BoundedAwait`, not a task group, which waits for its children), and a stream that did not stop is never "discarded". Keep the decision in a pure seam and test it with a start the test suspends.
- **An outcome event is not a final state.** The producer writes the outcome before `target-left`; the script exited 6 at the outcome. After an outcome keep waiting for `target-left` or `finished`, bounded, and test every order of the events (before, after, interleaved) with a fake that writes them with pauses. And never stop the producer before its outcome is final: wait, bounded, and when the bound runs out say `unknown` instead of staying silent.
- **A test that cannot fail on the old code proves nothing.** The late-result test only latched a gate and read its flags, so the old order (keep and dump, then look) passed it. Put the sequence after the await in a function (`LiveResultFlow.afterProvider`), suspend the provider on a continuation the test controls, latch while it is suspended, and run the same scenario through a copy of the old order to show that it fails there.

- **A terminal event must come after the cleanup it promises.** `target-left` and `finished` were written before the recording discard, which was only scheduled; a script that stopped Shep at the event killed the cleanup, and a keep that was already finalising could still publish. Await the cleanup, then write the event; latch the intent where the decision is taken (after the last await, and again under the lock right before the irreversible step); report the outcome as what happened (`recording-discarded` only when the removal succeeded, `discard-failed` and `recording-already-published` as their own events); and make the script wait for the outcome with a bound and say plainly when it did not arrive.
- **A notification carries its own facts: use them.** The activation callback ignored its payload and looked at the front app later, so away-and-back looked like nothing. Decide on the app the notification names; keep the poll as the backup.
- **State read from a background sink is shared state.** A flag on a main-actor object read inside a `@Sendable` closure is a race that minimal checking does not show. Put it in a small lock-protected `Sendable` holder and capture that, not `self`.
- **A dropped result is dropped everywhere.** The late result was not offered but was still written to the debug dump. One decision after the await (`LiveRunGate.decideResult`) says dump, offer and forward together.
- **"Every read is bound" needs an inventory.** The click's hit test read another app's element (role, actions, frame, identity) before the guard refused. Learn the owner from the pid alone and read nothing more unless it is the approved app. Say it exactly: the one read of a foreign element is `AXUIElementGetPid`; "reads nothing of another app" was too broad.

- **A binding checked once is a start-time check, not a binding.** `--live-target` looked at the front app at the start and at submission, then nothing: the person moved to another app while the card waited, and Shep docked over it, read its window metadata and may have sampled its title bar. A run bound to an app now stays bound from `target-ok` to `finished`: an activation observer and a 0.25 s poll watch the front app, and the tracker, planner and tint refuse every other app by one shared rule (`LiveBinding.mayRead`). The end of the run must be idempotent (a flag per way of ending), must cancel what waits (the card, the model answer, the clip) and must classify as its own status event, not as a refusal, or the script reports success. Shep's own window in front is not leaving.

- **Mode bits are not the whole permission on macOS.** An ACL can let another user add, delete or rename entries in a folder that reads 0700/0755. The trust rule now reads the ACL of the folder, every ancestor and the fresh work directory: an allow entry with add_file, add_subdirectory, delete_child, delete, write, security or owner rights passes only for us; deny entries and read-only grants pass (the home folder has a `group:everyone deny delete`, so a blanket "any ACL refuses" would break the default). Fail closed on an ACL that cannot be read or parsed. Test the rule through a seam AND with a real `chmod +a` on a temp directory the test made. The macOS function is `acl_get_perm_np`, not `acl_get_perm`.
- **Cleanup that can fail must not decide the exit status.** A removal chained with `&&` under `set -e` ended the script before `exit 8`. Handle a failed removal explicitly, say what remains and where, and keep the status. A fake that fails is the test.
- **A test suite cleans up what it made, by identity.** The script's own temp directory is removed at exit only if this process made it (path, pid, inode), it is a direct child of the temp directory with the expected prefix and not a symlink; older siblings with the same prefix are never touched. A nested harness proves the trap and the exit status.

- **A descriptor you hold does not bind the path you hand over.** ScreenCaptureKit opens a URL, so the held directory descriptor never saw the recorder's write: rename the private folder, leave a symlink at its old name, and the pixels land elsewhere. Judge the parent folder before the claim (resolved with realpath, owned by us, no group/other write, ancestors ours or root and not writable by others unless sticky), hand the recorder the resolved path, and re-check that the path still leads to the held directory and to the clip first seen before the start, after the first clip, every tick, before the stop and before publishing. That narrows the race and detects the rest; it does not make the write atomic, and a same-user process stays out of scope. Say so in the docs.
- **Own a file by what it is, not by its name.** `unlinkat(dir, "clip.mov")` removed whatever a same-user rename had put there. The slot now records the clip's (device, inode) the first time it is seen through the directory descriptor (regular, ours, one name), pins that inode with a read-only descriptor so its number cannot be recycled, and removes or publishes only that file; anything else is preserved with its directory and reported. A test must rename a different file over the clip and hard-link it, then compare bytes.
- **Verify the whole record, twice.** `--verify` checked id, pid and bundle, so a moved window or a reused id passed and the PNG disagreed with `SHEP_WINDOW_FRAME`. It now takes the frame and the title too, runs before the capture and again after it, and a mismatch after exits 8 with the app never run. The run removes only the PNG it reserved itself, after checking path type and inode, and says "removed nothing" if the name is no longer its file. No capture API binds the selected object: the second verify narrows churn, it is not atomicity.

- **Ownership is an identity, not an absence.** "The file was not there a moment ago" let the recorder claim a path another writer or a dangling symlink then held, and later delete it. A recording now owns a private working directory it created with mkdir (exclusive), holds it open, and removes only its own clip and directory after re-checking the identity; the final path is published with link(), which refuses instead of overwriting, and is never unlinked. Test with real directories and a hook that changes the world between the steps.
- **One decision, one read.** Consent was read for the dump and again inside the run, and a flip between the reads left an input dump with no send. Read it once at the start of the run, judge with that value, and put the dump hook inside the pipeline just before the provider call; assert the read count.
- **Never classify from a log that carries user text.** The request is printed on a log line, so it can contain any marker the classifier looks for. Scripts read a status file of closed events, created exclusively and tagged with a per-run nonce the request cannot know; the human log is for people and flattens control characters.
- **Id, pid and bundle must come from one record.** Three lookups can describe three windows. One snapshot gives all of them, the policy judges that record's bundle, and a fresh verify of the exact id, pid and bundle runs right before the capture. No fallback to "the first untitled window".

- **Cleanup that deletes "our file" must know it created it.** A script removed the output path whenever the recorder refused, and the recorder refused because that path already existed. Name the output uniquely, reserve it, never delete from the script, and let the writer delete only what it claimed when it was absent. A test that pre-creates the file and compares a checksum is the check that can fail.
- **A supplied value that does not parse is not an absent value.** A malformed `--live-target` was treated as no target and the run went to the front app. When a caller binds a request, an unusable binding refuses; only "nothing supplied" gets the default.
- **Policy before the side effect, in the same place.** The capture helper took the screenshot and let the Swift side refuse later; the file already existed. Check the policy (one shared list, fail closed) before the first write, and test the order.
- **A debug sink is a send path.** The dump ran before the cloud-consent gate and wrote raw text. Dump only what the gate has already allowed to leave, scrub the text, and say that the image is raw.
- **An exit code that ignores the log is not a result.** The dry run exited 0 after a refusal. Both modes now use one classifier with canned-log tests.

- **"Whatever is in front" is not a target.** The turtle request looked model-flaky; six identical CLI runs showed it was not. The live run read whichever app was frontmost at submission, so a browser the person switched to was read and correctly answered "no speed limit here". A live request now names its app (`--live-target`), waits for it, and looks again at the instant before anything is read; a run says which app it read. Measure with the dump before blaming the model.

- **A caller that drops its attestation on failure turns a refusal into a bare file.** The Swift side refused every unresolved target, but `e2e-glimmer.sh` exported the pid only when its lookup worked and otherwise ran on, so the CLI saw a window capture with no owner and took it for an unattested file. A failed lookup now stops the script before the capture, and the CLI refuses a frame plus a title with no owner. And a run that ends with nothing needs to say which stage said so (`[shep] live: reason:`), or two runs that differ cannot be told apart.

- **A recording bound to coordinates records whoever stands there.** The fix-demo recorder captured a fixed screen rectangle, so another app moving over it, or the target closing, was filmed and the capture policy never saw those frames. The recording is now window-bound inside Shep (the filter lists only the target window and Shep's own overlays) and the policy is polled while it runs; a stop deletes the partial file. An unnamed element is not an identity either: the sensitive-word policy cannot judge a label that is not there. And a test must name the type that declares the member (`GlimmerNaming.prompt`, not the protocol): one wrong name stops the whole test target.

- **Identity is resolved, never supplied; a fallback name is not an identity.** A click was bound to a rectangle and a role, so a different label at the same spot passed, and the CLI fell back to a made-up bundle id when the real one could not be read. The element under a click is now captured when the card is built and compared live; a named app is resolved through the system and refuses when it cannot be. Read window content only after deciding from metadata that the window is the target or a modal in front of it.

- **Approval is about a target, not a moment.** The click fallback validated, slept, then pressed; an app can change in that gap. Re-verify the window element and the control right before the event, with no await between, and treat a changed target as a new request that needs a new approval. A test that counts side effects in a loop (120 frames, one listener) catches the other kind of drift.

- **The first-choice call shortcut was taken twice.** Control-Option-Space is the Input Sources "select next source" shortcut and Control-Option is VoiceOver's modifier (VO-Space activates the item under the cursor); a shortcut for an assistive entrance must not shadow VoiceOver. The default is Control-Shift-Command-Space; `HotKeySpec.systemConflict` knows the usual space-bar suspects and a test pins the default as conflict-free.
- **Log coordinates must name their space.** The tracker log printed the tab rectangle in Cocoa (bottom-left) coordinates beside an AX (top-left) window frame, and `scripts/capture-lib.sh` read it as top-left. Every rectangle a script reads is now printed in global top-left points, and `HomePlacement` / `TravelPath` have log helpers that take the primary screen's height.
- **Stopping a tracker must forget what it published.** `WindowTracker.publish` skips an unchanged observation, so after stop / start with the same front window the owner never heard again and stayed hidden. `stop()` clears `hasPublished` and the last observation.
- **A stale frame flashes when a panel returns.** A web view shown again after being ordered out may composite its last frame for a frame or two; the traveller panel orders front 40 ms after the page was told to travel (first sample is invisible).
- **Timers from an earlier phase must not act.** Every phase that schedules work (`ShepCoordinator.epoch`) bumps a counter and its delayed blocks check it, so "called again on the way home" or "sent home while waking" cannot be hit by the previous phase's `arrived` / `sleep` timer.

- **Dock as a tab, not a floating head.** A dog floating over the title bar read as an overlay, not part of the window. The tab's base must sit exactly on the window's top edge, share the bar's fill, and have no outline along the base. Room above is the usable screen area (menu bar excluded), not the full screen frame.

- **A docked overlay must not guess the middle of the title bar.** A fixed 62% x position covered the document title in the first Mac screenshot. The dog now sits at the right end and steps left past AX title-bar items.
- **Glimmer thinking is off only with `reasoning_strength: "none"`** (top-level request field). `enable_thinking`, `chat_template_kwargs` and `/no_think` do nothing. Its boxes are 0-1000 relative to the image.
- **A detector box inside a window-sized AX container is not a duplicate.** De-dup uses IoU, or "mostly inside a box of comparable size" (area ratio <= 3), never plain containment.

- **Xcode 27: spell out `CGFloat.nan` / `CGFloat.infinity`** in CGRect/CGPoint inits (bare `.nan` is ambiguous). Keep that habit for any new geometry test.
- **mlx_vlm loads the model a request names.** Send the exact `--model` path the server started with, or it may load a second 18 GiB copy. Check free memory before starting (scripts/glimmer-server.sh refuses under 24 GB) and reuse a running server.
- **A transparent panel over other apps must not eat clicks.** `ignoresMouseEvents` is true except over the dog/card; toggle it from mouse-moved monitors. A synthetic click must first hide the panel, or the AX hit test at the target answers with Shep's own window.
- **Keep banned words out of the source tree.** `scripts/check-rules.sh` and `SourceRulesTests` grep Swift/shell for scripting-bridge automation and other local models, comments included; build the patterns from pieces so the checker does not trip on itself.
- **Some Swift is written without a compiler at hand.** Code written away from a Mac is compiled only later. Prefer simple, explicit code; avoid clever generics, result builders outside SwiftUI views, and Swift 6 concurrency. SWIFT_VERSION is 5.0 with `SWIFT_STRICT_CONCURRENCY: minimal`.
- **AX API shapes:** `AXUIElementCopyAttributeValue(el, attr as CFString, &value)` returns `AXError` and fills a `CFTypeRef?`; check `CFGetTypeID` before `as! AXValue` / `as! AXUIElement`. `AXValueGetValue(v, .cgPoint, &p)` returns Bool. The `kAX…` constants are Swift `String`s. The `AXObserverCallback` is a C function pointer: use a file-level function, pass `self` through `refcon` with `Unmanaged`.
- **AX coordinates** are top-left origin on the primary screen; Cocoa is bottom-left. Convert with the *primary* screen height (`NSScreen.screens[0]`), for every screen, including ones with negative origins.
- **Moved/resized notifications** come from the window element, not the app element, so they must be re-registered when the focused window changes. Polling at 0.25 s covers apps that do not send them.
- **Accessibility trust is tied to the code signature.** Ad-hoc / unsigned Debug builds can lose the grant on every rebuild: remove and re-add Shep in System Settings › Privacy › Accessibility when docking stops working.
- **Unsigned test bundles:** if `scripts/test.sh` fails to load the test bundle with `CODE_SIGNING_ALLOWED=NO`, retry with `CODE_SIGN_IDENTITY=- CODE_SIGNING_ALLOWED=YES`.
- **bloub is read-only.** Build the dog page from a temp copy (`tools/shep-dog/build.sh` symlinks its `node_modules`), never inside the bloub checkout itself (`BLOUB_DIR`).
- **BSD `stat -f %Lp` drops the sticky bit.** macOS prints 777 for a 1777 directory; use `%Mp%Lp` (or `lstat` `st_mode`). GNU `%a` already includes it, so a check that passes on Linux can fail on the Mac. Test with a fake `stat` (`FIX_STAT_CMD`), not the platform's.
- **Unreadable is not "no ACL".** `ls -led` failing for any reason other than a positively identified GNU ls (`--version` + "invalid option") must refuse, and its output must be validated (header shape, `+` marker vs ACL lines, every rights token against a whitelist). Never split rights with an unquoted expansion: `*` globs the cwd.
